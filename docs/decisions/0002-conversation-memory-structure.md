# 0002. 会話の記憶を CLAUDE.md + 決定ログで永続化する

- **日付**: 2026-08-28
- **状態**: 採用
- **関係する場所**: `CLAUDE.md`, `docs/`

## 背景

Claude との会話は 2 つの理由で失われる。

1. **セッション内**: 長くなると自動要約（auto-compact）が走り、細部と「捨てた案の理由」から消える
2. **セッション間**: 新しいセッションは前回を一切覚えていない。
   特に Claude Code on the web はコンテナが使い捨てで、**git に push したものしか残らない**

その結果、毎回同じ説明を繰り返し、同じ検討をやり直していた。

## 決めたこと

リポジトリ内に記憶層を作る。

| 階層 | 役割 | 読み込まれ方 |
|---|---|---|
| `CLAUDE.md` | 索引と常時ルール。**薄く保つ** | セッション開始時に自動 |
| `docs/context/` | 現状の事実（構成・規約） | 必要なときだけ手動 |
| `docs/decisions/` | 判断とその理由 | grep でオンデマンド |

## 検討して捨てた案

- **CLAUDE.md に全部書く**: 自動で読まれるぶん確実だが、肥大すると毎回コンテキストを圧迫し、
  かえって精度が落ちる。索引に留め、本体は外に置く。
- **Vault 全体を読ませる**: ノートが増えるほど破綻する。オンデマンド検索の形にする。
- **専用のツールやスクリプトを組む**: 素の Markdown なら `grep` / `cat` でそのまま読めるし、
  人間も Obsidian でも GitHub でも読める。仕組みを足す必要がない。

## 結果と影響

- 説明の再入力が減る。決定の理由が残る
- 反面、**書かなければ意味がない**。`/decide` コマンドで摩擦を下げる
- 情報の鮮度管理が必要。`docs/context/` は「最終確認日」を書き、古くなったら直す
