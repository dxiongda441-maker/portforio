# 0004. トランプゲーム集は「1ゲーム1ファイル＋共通進行管理」で、SW なしの静的アプリにする

- **日付**: 2026-09-25
- **状態**: 採用
- **関係する場所**: `projects/family-cards/`

## 背景

年末に家族で遊べるトランプゲーム集（ババ抜き・大富豪・ポーカーなど）を作品として追加した。
10 種類のゲームを 1 つのアプリに入れるため、既存作品の「`index.html` + `app.js` + `styles.css`」
の 3 ファイル構成では `app.js` が数千行になり、ゲーム単位で直せなくなる。

また「1 台の端末を家族で回す」遊び方と「CPU 相手」の遊び方を、全ゲームで同じ仕組みにしたかった。

## 決めたこと

- `core.js` に共通部品を置く: カード生成・描画、`Session`（進行管理）、席・手札の描画ヘルパー。
- 各ゲームは `games/<id>.js` の 1 ファイルで完結させ、`registerGame({...})` で登録する。
  ゲーム本体は `async play(session)` を上から素直に書き、最後に順位の配列を返す。
- 人の操作は `session.ask()` / `session.answer()`、CPU の間は `session.sleep()` で待つ。
  「やめる」を押すと `session.abort()` が待ちをすべて `Aborted` で打ち切る。
- 人間が 2 人以上いるときは、その人の番の前に「端末を渡す」画面を挟み、手札は自分の番のときだけ表示する。
- スクリプトは ES Modules ではなく通常の `<script>` を順番に並べる。
- Service Worker は付けない（PWA にしない）。

## 検討して捨てた案

- **案A: `app.js` 1 本にまとめる** — 他作品と揃うが、10 ゲームで数千行になり、1 ゲームの修正で全体を読む必要が出る。
- **案B: ES Modules（`import`）で分割** — `file://` で開くと CORS で動かない。家族に HTML を渡して開いてもらう使い方も残したかった。
- **案C: PWA にしてオフライン対応** — 年末の帰省先で使う想定には合うが、SW を持つと編集のたびに
  `CACHE_NAME` の更新と `APP_SHELL` へのファイル追加が必要になる（`docs/decisions/0003`）。
  ゲームを足したり直したりする頻度が高い初期段階では、その手間と取りこぼしのリスクが大きいので見送った。
- **案D: ネット対戦** — サーバーが要る。静的サイトの方針（`0001`）から外れる。

## 結果と影響

- ゲームの追加は「`games/` にファイルを 1 つ作る＋ `index.html` に `<script>` を 1 行」で済む。
- `?speed=0` を付けると CPU の待ち時間がほぼ無くなり、全員 CPU（観戦モード）で最後まで自動で進む。動作確認に使える。
- オフラインでは開けない。帰省先での利用が多いと分かったら、案C（PWA 化）を見直す。
  その場合は作品固有の `CACHE_PREFIX`（例: `family-cards-`）を切ること。
