# 0004. セキュリティ・クエストは章ごとのデータファイル＋非PWAの静的アプリにする

- **日付**: 2026-10-23
- **状態**: 採用
- **関係する場所**: `projects/security-quest/`

## 背景

セキュリティを体系的に学べる学習ゲームを作品として追加した。
全18章・講義104枚・問題186問・用語307語と、既存作品よりデータ量がひと桁多い。
また題材がセキュリティなので、作品自体が「やってはいけない実装」を含んでいると説得力がなくなる。

## 決めたこと

- エンジンは `app.js` 1本、データは `data/acts.js` ＋ `data/ch01.js`〜`ch18.js` に章単位で分割する。
  各章ファイルは `SQ.chapters.push({...})` するだけ。`<script defer>` を順に並べて読み込む（ビルドなし）。
- 問題形式は `choice` / `multi` / `order` / `input` / `spot` / `match` の6種。判定は `app.js` の `judge()`。
  問題IDは章ID＋配列の位置から自動採番する（`c03-5` など）。
- 進捗は `localStorage` の `security-quest-v1` にだけ保存する。外部送信なし。
- `<meta http-equiv="Content-Security-Policy">` で外部スクリプトと外部通信（`connect-src 'none'`）を禁止。
  画面描画で `innerHTML` を使わない（太字とコードだけを自前でパースして DOM を組む）。
- **PWA にしない**（Service Worker なし）。

## 検討して捨てた案

- **案A: `contracts` と同じく `data.js` 1本** — 200KB 超の1ファイルになり、章単位で直すときに差分も見づらい。
- **案B: ES Modules（`import`）で分割** — `file://` で開くと CORS で読み込めず、README の「直接開いても動く」に反する。
- **案C: PWA 化してオフライン対応** — `CACHE_NAME` の版上げ運用（`docs/decisions/0003`）を19ファイルぶん背負うことになる。
  学習ゲームでオフラインの必要性は低い。必要になったら `CACHE_PREFIX = "security-quest-"` で追加する。
- **案D: 攻撃手法の実践章（偵察・スキャン等）** — 当初の第18章案。攻撃の具体的手順に寄りすぎるため、
  防御の総合演習「守りを設計する」に差し替えた。攻撃側の概念は各章の中で防御とセットで扱う。

## 結果と影響

- 章を足すときは `data/chNN.js` を作り、`index.html` の `<script>` に1行足すだけ。
- **問題の順番を入れ替えたり途中に挿入したりすると、問題IDがずれて復習リスト（`wrong`）の対応が崩れる。**
  存在しないIDは無視されるので壊れはしないが、復習対象が別の問題に化けうる。追加は配列の末尾に。
- 法令・規格・統計など時間で変わる内容を含む（個人情報保護法の報告期限、NIST CSF 2.0、OWASP Top 10 の順位など）。
  改正があれば該当章を直すこと。
