# 0005. 心理学クエストは security-quest のエンジンを複製して作り、範囲は心理学検定と公認心理師の出題基準で決める

- **日付**: 2026-10-23
- **状態**: 採用
- **関係する場所**: `projects/psychology-quest/`、`projects/security-quest/app.js`、`tools/check-learning-game.js`

## 背景

`/learning-game 心理学` で、セキュリティ・クエスト（`docs/decisions/0004`）と同じ仕組みの学習ゲームを作った。
目標は「全章クリアで心理学をほぼ一通り理解し、研究や事例を見て判断できる」こと。
決める必要があったのは、①エンジンを共有するか複製するか、②範囲をどこまでとし、何を根拠にするか、
③心理学という題材ならではの配慮（自己診断・心の不調への接し方）をどうするか。

## 決めたこと

- **エンジンは `app.js` を複製**し、分野固有の部分だけ書き換える。
  `STORAGE_KEY = "psychology-quest-v1"`、`SAVE_PREFIX = "PQ1."`、称号、導入文、遊び方、修了証の参考リンク、最終ボス名。
  データ形式・問題形式・CSP・非PWA は 0004 と同じ。
- **範囲は4幕18章**（科学の章／しくみの章／人の中の章／支援の章）。
  心理学検定の10科目（A領域：原理・研究法・歴史、学習・認知・知覚、発達・教育、社会・感情・性格、臨床・障害／
  B領域：神経・生理、統計・測定・評価、産業・組織、健康・福祉、犯罪・非行）と、
  公認心理師試験の出題基準の大項目を、どの章が受け持つか対応させて抜けを確認した。
- 第18章は security-quest の「守りを設計する」に相当する**総合演習**にし、疑似科学の見分け方、俗説、
  有名研究の追試結果（スタンフォード監獄実験・マシュマロ・テスト・自我消耗・パワーポーズ）、データの読み方、事例の見立てを扱う。
- 遊び方ページに「つらいときは」の節を置き、厚生労働省「まもろうよ こころ」へリンクする。
  「このゲームを修了しても他人や自分を診断できるようにはならない」と明記する。
- 問題の品質は 0004 のルールに加え、**正解の長さの順位**も見る。最長を避けようとして短く書き直すと、
  今度は「2番目に長い」に正解が集中した（初稿で 58%）。そこで `tools/check-learning-game.js` に順位の分布を出す行を足した。

## 検討して捨てた案

- **案A: エンジンを `projects/_engine/app.js` に共通化して両作品から読む** — 作品ごとに独立した静的アプリという
  リポジトリの前提（`docs/context/architecture.md`）を崩し、片方の修正がもう片方を黙って壊しうる。
  2作品なら複製の方が安全。3作品目を作るときに改めて検討する。
- **案B: 公認心理師の法制度・職責だけで独立した章を作る** — 時間で変わる内容の比重が大きくなり、
  心理学そのものの理解という目標から外れる。第17章の講義1枚（業務・義務・秘密保持の例外）に絞った。
- **案C: 人体の構造と機能、精神科の薬理を詳しく扱う** — 医学の範囲で、クイズで正確さを保つ負担が大きい。
  第4章（神経伝達・脳部位）と第16章（薬物療法の概要と、心理職は服薬の指示をしないこと）までにとどめた。
- **案D: 診断名を当てる問題を多くする** — 「素人診断」を練習させることになる。精神疾患の章でも、
  状態の理解と「誰につなぐか」を問う問題を中心にし、第18章で素人診断をしないことを扱った。

## 結果と影響

- **エンジンを直すときは両方の `app.js` を直す。** 今回見つかった `el()` の不具合
  （`children.flat()` が1段しか平らにせず、用語図鑑が `[object HTMLElement]` と表示されていた）は、
  security-quest も含めて `flat(Infinity)` に直した。
- 時間で変わる内容を含む：DSM-5-TR／ICD-11、公認心理師法、ストレスチェック制度（50人未満への拡大の施行時期）、
  障害者差別解消法（2024年4月から民間事業者も合理的配慮が義務）、いじめ防止対策推進法。改正があれば第15・17章を直す。
- 公認心理師の出題基準は、作成時の環境から厚生労働省の PDF を取得できず、大項目の対応は記憶に基づく。
  最新版と突き合わせて確認すること。

## 追記（2026-10-24）：RPG 風のストーリーと「つよさ」画面

ユーザーの要望で、ドラクエ／ポケモンのようなストーリー性と、ドラクエのようなステータス確認・成長速度の可視化を足した（心理学クエストのみ）。

- ストーリーは問題データと分けて `data/story.js` に置いた。問題の配列に触れないので、問題IDと復習リストは変わらない。
  既存の各章の `story`（現実の研究室の出来事）はそのまま「現実の世界では——」として残し、その奥にある心の世界「ココロの国」で霧の主と戦う二重構造にした。
- レベルは累計 EXP から計算する（`expForLevel`：全章撃破＋最終試験合格でおよそ Lv29）。HP・MP はレベルから決まる成長の目安で、バトルのライフ（♥）とは別。
  バトルの難しさ（撃破80%・最終85%）は変えていない。
- 能力値は飾りの数字にせず、学習データから出す：幕ごとの撃破率と正答率（4種）、直近50問の正答率、復習ダンジョンの卒業数、学習した日数。
- 成長速度は、戦うたびに日付・正解数・獲得EXPを `log` に残し、「1日ごとの獲得EXP（14日）」「バトルごとの正答率（20戦）」の棒グラフ、
  直近7日のペースからの「つぎのレベルまであと何日」「全章撃破まであと何学習日」の予測で見せる。

### 検討して捨てた案

- **案E: 能力値をドラクエと同じ名前（ちから・すばやさ等）にする** — 学習との対応が分からず、数字が何を意味するか説明できない。学習の中身に対応する名前にした。
- **案F: レベルでバトルを有利にする（HPでライフが増える等）** — レベル上げで知識なしに勝てるようになり、学習ゲームの目的に反する。
- **案G: 外部のグラフライブラリを使う** — CSP で外部スクリプトを禁止している。棒グラフは DOM と CSS で描き、値はホバー／フォーカスの読み上げと「表で見る」でも読めるようにした。

### このとき見つけて直した不具合

- 正解したときの解説欄に「null」と表示されていた（DOM の `append()` に `null` を渡すと文字列になる）。security-quest にも同じ不具合があり、両方直した。
  心理学クエストは画面への追加を `mount()` に集め、`null` を除いてから追加する。
