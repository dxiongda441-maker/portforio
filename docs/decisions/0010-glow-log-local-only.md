# 0010. 自分磨き記録アプリ Glow Log は、写真も記録も端末内（IndexedDB）だけに置く

- **日付**: 2026-11-06
- **状態**: 採用
- **関係する場所**: `projects/glow-log/`

## 背景

本人が毎日、顔と体の写真・体重を記録し、健康状態と改善点を残せるツールを求めた。
扱うのは上半身裸の写真や体重といった、公開リポジトリ・公開サイトに絶対に出してはいけない情報。
一方でサイトはビルド工程なしの静的サイトで、サーバー側の保存先を持たない。

## 決めたこと

- `projects/glow-log/` に PWA として置く。保存先はブラウザの IndexedDB（写真は JPEG の Blob、長辺 1440px）。
- `<meta>` の CSP で外部通信を禁止し、写真がどこにも送られないことを仕組みで担保する。
- 消失対策は `navigator.storage.persist()` ＋ ホーム画面への追加の案内 ＋ JSON（写真込み）/CSV の書き出し。
- AI への相談は、数値だけを文章にまとめてコピーする方式（写真は含めない。送るかどうかは本人が選ぶ）。
- **本人の実データ（体重・写真・評価）はリポジトリに入れない。** サムネイル用の画面は架空のデモデータ（図形のシルエット）で撮った。

## 検討して捨てた案

- **localStorage に保存**: 容量が約5MBで写真が数枚しか入らない。文字列化も重い。
- **Claude の Artifact（共有DB・アセット保存）で作る**: Claude から記録を直接読めるのは利点だが、裸の写真をサーバーに上げることになり、本人の同意範囲を超える。
- **クラウド同期（Firebase など）**: 静的サイト・npm なしの方針（0001）に反し、認証と個人情報の管理責任が生じる。
- **ポートフォリオに載せず別リポジトリにする**: iPhone のホーム画面に置くには HTTPS の公開先が必要で、既存の Pages を使うのが最短。アプリ自体は個人データを含まない汎用ツールなので作品として載せても問題ない。

## 結果と影響

- 端末を変える・ブラウザのデータを消すと記録が消える。書き出しを習慣にしてもらう必要がある。
- 同一オリジンの他作品とは IndexedDB の DB 名（`glow-log`）と SW の `CACHE_PREFIX`（`glow-log-`）で分離している。
- 将来クラウドへ移す（0009）場合も、オリジンが変わると IndexedDB は引き継がれない。移行前に書き出し→読み込みが必要。
