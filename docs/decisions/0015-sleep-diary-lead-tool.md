# 0015. 睡眠の発信の入口として、CBT-I の睡眠日誌 PWA「ねむり日誌」を端末内保存で作る

- **日付**: 2026-11-24
- **状態**: 採用
- **関係する場所**: `projects/sleep-diary/`

## 背景

「研究で効果が確かめられているのに人々に届いていないもの」を調べ、不眠の認知行動療法（CBT-I）を最有力とした。
慢性不眠の第一選択（ACP ガイドライン 2016、Trauer 2015 のメタ分析）だが、日本ではプライマリケアでほぼ行われず薬物療法が中心。
一方で患者の半数以上は薬より CBT を選びたいと答えている。
本人の方針は「睡眠の発信 → リスト獲得 → 解決する商品を販売（記録ツール・アフィリエイト）」。
相談の結果、記録ツール単体は無料アプリと競合して売りにくいため、**無料の入口**として作り、有料は「記録から行動を変えるプログラム」にする方向にした。

## 決めたこと

- `projects/sleep-diary/` に PWA として置く。保存先は IndexedDB（DB名 `sleep-diary`）。SW の `CACHE_PREFIX` は `sleep-diary-`。CSP で外部通信を禁止（Maru Log と同じ）。
- 記録項目は Carney 2012 のコンセンサス睡眠日誌の中心項目（床に入った・消灯・入眠潜時・中途覚醒回数と時間・最終覚醒・離床・満足度）。
- 2週間（14夜）を1区切りにする。7日で5夜あれば「眠る時間の目安」（睡眠制限法をゆるめたもの）を出し、1週間ごとに睡眠効率で ±15分調整。
- **目安の下限は6時間**。臨床の睡眠制限法より安全側。はじめる前の確認（睡眠時無呼吸の疑い・強い日中の眠気・双極性障害/てんかん・妊娠・交代勤務・むずむず脚・18歳未満・強い抑うつ）に1つでも当てはまれば目安を出さない。抑うつの項目には相談窓口を出す。
- 「治る」「治療」など効果をうたう表現を使わない。医療機器ではない旨を明記（薬機法上のプログラム医療機器に当たらないようにするため。法的な確認はしていない）。
- メール登録は外部フォームへのリンク（`SIGNUP_URL`）。日誌データは送らない。登録先が決まるまで空にして「準備中」と表示。

## 検討して捨てた案

- **Maru Log や Glow Log に睡眠タブを足す**：入口として単独で配れる URL が要る。別アプリにした。
- **記録をサーバーに送ってメールで週次レポートを届ける**：静的サイトのままでは不可。健康情報を預かる責任も重い。レポートは端末内で作り、コピーで持ち出す形にした。
- **臨床どおり下限5時間**：医師の管理がないため採らない。
- **行動タグの効果を「よい/悪い」で色分け**：少ない記録では偶然の差が大きく、「カフェインで眠りがよくなった」のような誤解を生んだ。中立の「記録上の傾向」として表示し、両側3夜以上に限った。

## 結果と影響

- 登録フォームと有料プログラムは未作成。`SIGNUP_URL` を入れるまで、リスト獲得の導線は働かない。
- 端末を変えると記録は消える（書き出し/読み込みあり）。Cloudflare 移行（0009）でオリジンが変わると IndexedDB は引き継がれない。
- アフィリエイトを載せる場合はステマ規制（2023年10月〜）の「広告」表示が必要。アプリ内には載せていない。
