# 論文メモ: LLM で購買意向アンケートを再現する（SSR 法）

- 論文: Maier ほか「LLMs Reproduce Human Purchase Intent via Semantic Similarity Elicitation of Likert Ratings」arXiv:2510.08338（v3, 2025-10）
- 著者の所属: PyMC Labs、Colgate-Palmolive
- 実装: https://github.com/pymc-labs/semantic-similarity-rating（Python）
- 読んだ日: 2026-11-22

## 一言で

LLM に「1〜5 で答えて」と聞くと、ほぼ全部「3」になって使えない。
**自由文で答えさせ、その文を「基準文 5 つ」との意味の近さ（埋め込みの cosine 類似度）で 1〜5 の確率分布に変換する**と、
人間のアンケート結果をかなり正確に再現できる。これを SSR（Semantic Similarity Rating）と呼ぶ。

## やり方（手順）

1. **ペルソナを作る**: 年齢・性別・地域・収入などの属性を system prompt で与え、「アンケート回答者を演じて」と指示する。
2. **商品案を見せる**: 説明文（＋画像）を提示し、「この商品をどのくらい買いたいですか？」と聞く。
   system prompt に「質問には短く答えて」と入れる。1 ペルソナにつき 2 回サンプリング（temperature 0.5, top_p 0.9）。
3. **自由文の回答を得る**: 例「少し気になる。効果があって高すぎなければ試すかも」。
4. **基準文と比べる**: 1〜5 それぞれに対応する短い基準文（例: 5=「きっと買うと思う」/ 1=「買う可能性はかなり低い」）を用意し、
   回答文と各基準文の埋め込み（論文では `text-embedding-3-small`）の cosine 類似度 γ を出す。
5. **確率分布にする**: `p(r) ∝ γ(r) − min(γ)`（5 つの中で最小の類似度を引いて、合計 1 に正規化）。
   最小値を引かないと差が小さすぎて分布がほぼ平らになる。
   基準文セットは言い回しを変えて **6 セット作り、分布を平均**する（言い回しへの依存を減らす）。
6. **集計**: 全ペルソナの分布を平均して、その商品案の回答分布と平均購買意向を得る。

## 結果（57 件の実アンケート、回答者 9,300 人との比較）

| 方式 | 商品の順位の再現（相関の到達率 ρ） | 回答分布の近さ（KS 類似度） |
|---|---|---|
| 数字で直接答えさせる | 約 80% | 0.26〜0.39（ほぼ全部「3」） |
| 自由文 → LLM に 1〜5 を付けさせる | 85〜90% | 0.59〜0.72 |
| **自由文 → SSR** | **約 90%** | **0.80〜0.88** |

- ρ は「同じアンケートを人間でやり直したときの一致度」を 100% とした割合。つまり人間の再テスト並みの約 9 割。
- **ペルソナ属性を外すと**分布は人間にそっくり（KS 0.91）になるが、商品の順位はほぼ当たらない（ρ 50%）。
  → 属性を入れないと「何でも高評価」になり、商品の良し悪しを見分けなくなる。**属性は必須**。
- 年齢・収入による差は人間と似た傾向を再現した。性別・地域・民族は再現が不安定。
- 学習データ不要（ゼロショット）。人間データで学習した LightGBM（ρ 65%）より良かった。
- 自由文があるので「なぜ買う/買わないか」の理由も取れる。人間の自由記述より情報量が多い。

## 限界（論文自身が書いていること）

- 基準文は 57 件のアンケートに合わせて手で調整したもの。別の題材で同じ精度が出るかは不明。
- 歯磨き・ボディケアのように **ネット上に消費者の声が多い分野だから** うまくいった可能性が高い。情報の少ない分野では当てにならない。
- 実際の購買（予算・文化・広告接触）までは再現できない。あくまで「コンセプト段階の当たりを付ける」道具。

## このサイトでの使い道（提案）

主目的は副業の営業（`service/` = 小さなお店向けホームページ・Instagram・AI 活用、月 1 万円〜）。
SSR は「**公開前に、どの書き方・どの料金案が刺さりそうかを安く比べる**」用途に向く。

1. **service/ の訴求文・料金案の比較（最優先）**
   - ペルソナ: 個人経営のカフェ・パン屋・焼き菓子店の店主（年齢・店の規模・IT への慣れ・月の売上感・今の集客手段を変えて 50〜100 人分）。
   - 刺激: `service/` の見出し＋料金表のテキスト版を、A 案・B 案…と差し替えて提示。
   - 質問: 「このサービスに申し込みたいと思いますか？」→ SSR で 1〜5 の分布 → 案ごとの平均と分布を比較。
   - 自由文の「申し込まない理由」を集めて、FAQ や不安の解消文に反映する。
2. **ほかの指標にも使える**: 論文では「関連性がある商品か」でも ρ 82% 程度。「信頼できそうか」「料金は妥当か」も基準文を作れば測れる。
3. **お客さん向けの提案材料**: AI 活用メニューとして「新商品・新メニュー案の事前評価」に応用できる（ただし精度保証はできない、と明示する）。

### 使うときの注意

- 結果は **人間の声の代わりではなく、当たりを付ける道具**。最終判断は実際のお客さんの反応で。
- 論文の検証は米国・英語・日用品。**日本語・個人向け Web 制作サービスでの精度は未検証**。
  基準文は日本語で書き直し、言い回し違いで複数セット作って平均する。
- 属性は必ず入れる（入れないと全部高評価になる）。
- API キーと費用が必要（生成用 LLM ＋ 埋め込みモデル）。100 ペルソナ × 2 回 × 案数ぶん呼ぶ。
- このリポジトリはビルド工程なしの静的サイトなので、**評価用スクリプトはサイト本体に組み込まない**（手元か別リポジトリで動かす）。
